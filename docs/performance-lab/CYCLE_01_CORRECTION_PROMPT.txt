CURRENT EVIDENCE
- Real XeOS: presentations average about 5 seconds to open.
- Secure PPTX open currently reads the File into bytes, validates the whole PPTX, then delegates to the original controller, which calls file.arrayBuffer() again.
- Security validation must remain exactly as strict as before.
- Do not change duplicate CRC/ZIP work in this cycle; isolate the effect of the duplicate File read first.

CYCLE 01 GOAL
Eliminate the second underlying File.arrayBuffer() read for a successfully validated PPTX while preserving the exact validation and decode sequence otherwise.

PREFERRED MINIMAL DESIGN
- In PresentationPolicy secureController().create().openFile(), after reading and validating bytes, delegate to the existing inner.openFile() through a minimal validated file-like object whose arrayBuffer() returns the already-read ArrayBuffer.
- Preserve name/type/size/lastModified metadata needed by downstream code.
- Do not expose a bypass that lets unvalidated bytes enter the decoder.
- Do not alter the original decoder's CRC behavior in this cycle.
